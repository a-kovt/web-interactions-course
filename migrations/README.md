# Міграції

Файли `NNN_name.sql` застосовує сервіс `migrate` під час `docker compose up`: по черзі, кожен
один раз і в одній транзакції (`NNN_name.notx.sql` – без транзакції). Застосований файл не
змінюють. Для нової зміни схеми створюють новий файл.

```sh
docker compose run --rm migrate sh /migrate/migrate.sh --list
```

Каталог `examples/` містить схему й тестові дані області «Міська бібліотека». Вони не
застосовуються автоматично.

У ЛР6 зміна проходить етапи розширення схеми (expand) → перенесення даних → перемикання прапорцем функції → скорочення
(contract) окремою міграцією.
Поки скорочення не можна виконувати, задайте в `.env` `MIGRATE_TO=NNN`, і `migrate`
зупиниться після цієї версії.

Режими без захисту запускайте на окремих тестових даних. `docker compose down -v` видаляє томи,
і наступний запуск створює базу заново.
