# Спільний проєкт Web + DPC

Для спільної теми C01–C30 один проєкт закриває ядро обох курсів. Розділ 6 картки DPC визначає,
яка частина змінює який стан. Кожен курс можна виконати й окремо. Тоді відповіді та події
відсутньої частини відтворюють генератори й імітатори.

## Структура інтеграції

Корінь кожного комплекту – проєкт курсу. Нижче наведено можливу структуру спільного проєкту з окремими каталогами компонентів і спільним `compose.yaml`.

```text
my-project/
  web/            # комплект Web і ваш код
  dpc/            # комплект DPC і ваш код
  compose.yaml    # спільний запуск
  checks.yaml
  ...
  README.md       # архітектура й результати обох курсів
```

Спільний `compose.yaml` може підключити обидва файли курсів, коли збіги імен усунуто. Як їх
усунути, описано після прикладу.

```yaml
include:
  - web/compose.yaml
  - dpc/compose.yaml
```

Порти комплекту Web не перетинаються з портами DPC. З комплектом DPC збігаються імена сервісів
`postgres`, `migrate`, `kafka-ui`, `prometheus`, `grafana` і томів `pgdata`, `faults`. Перейменуйте
їх в одному з файлів або залиште по одному спільному. Брокер Web називається `broker`, у DPC –
`kafka`. Для спільного Kafka залиште один і задайте обидва імена (`networks.default.aliases`)
або змініть адреси в змінних. Шляхи `build` і томів кожного файлу відраховуються від каталогу цього файлу.

## Одна частина без другої

Якщо тему C01–C30 виконують лише в курсі Web, дії частини DPC відтворюють засоби комплекту:

- події, які публікувала б частина DPC, – файл JSONL від `tools/make_events.py` і `tools/jsonl_to_kafka.py`
- HTTP-запити, які надсилала б частина DPC, – сценарій `tools/workload`
  за зразком `tools/workload/scenario.example.py`

`tools/make_events.py` пише рядки CloudEvents за списком ідентифікаторів, а `tools/jsonl_to_kafka.py`
надсилає їх у тему Kafka (topic) обробника. Запуск обох команд наведено в шапці `make_events.py`.
Ті самі аргументи дають ті самі ідентифікатори подій, тому повторне надсилання – це дубль, який
обробник має застосувати один раз. Дані, які в спільному проєкті належать DPC, задайте початковими
даними за розділом 6 картки.

## Перевірка й опис

- [checks-template.yaml](checks-template.yaml) → `checks.yaml` у корені спільного проєкту –
  налаштування частин у розділах `web:` і `dpc:` та кроки наскрізного сценарію в `scenario:`.
- [scenario.example.py](scenario.example.py) → `joint/my-scenario.py` – приклад передавання
  ідентифікатора між API для `tools/workload` (створення у Web → обробка в DPC → результат у Web).
  Команда запуску – у шапці файлу.
- Межу частин опишіть у README проєкту в підрозділі «Спільний проєкт» за шаблоном
  [README-template.md](../README-template.md).
