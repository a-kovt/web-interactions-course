# Симулятор зовнішньої системи (ЛР4)

Повільний постачальник із вашої картки (платіжний шлюз, кур'єр, замок самоката). Працює як
сервіс `external-sim` (порт 8090). Налаштування задають змінні `SIM_*` у `.env`.

| Змінна | Типово | Що задає |
|---|---|---|
| `SIM_NAME`, `SIM_ROUTE` | `provider`, `/operations` | назва постачальника й маршрут операції |
| `SIM_DELAY_MS` | `1000-8000` | затримка відповіді |
| `SIM_REJECT_SHARE`, `SIM_REJECT_REASONS` | `0.2` | частка відмов за змістом і їхні причини через `\|` |
| `SIM_ERROR_SHARE` | `0.05` | частка тимчасових `503` |
| `SIM_SEED` | порожньо | відтворюваний вибір результату й затримки |
| `SIM_STATE_FILE` | `/data/state.jsonl` у Compose і Swarm | файл збережених результатів. Його каталог підключено як постійний том |

| Маршрут | Що робить |
|---|---|
| `POST {SIM_ROUTE}` з `Idempotency-Key` | `200` зі `status: accepted` чи `rejected` або `503` |
| `GET /effects?key=…` | ефекти за ключами – на кожен ключ не більше одного |
| `POST /admin/unavailable?seconds=N` | `503` на всі нові звернення N секунд |
| `POST /admin/reset` | забути все (409, поки операції виконуються) |

За наявності `SIM_STATE_FILE` на збереженому томі симулятор пам'ятає остаточний результат за ключем і після перезапуску. Тому повтор не створює
другого ефекту. Відповідь `503` не запам'ятовується. Ключ – ідентифікатор вашої операції.

Приклад для `SIM_ROUTE=/deliveries` з `.env.example`:

```sh
curl -s -X POST localhost:8090/deliveries -H "Idempotency-Key: op-1" -d '{}'
curl -s "localhost:8090/effects?key=op-1"
curl -s -X POST "localhost:8090/admin/unavailable?seconds=30"
```
